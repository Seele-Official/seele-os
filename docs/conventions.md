# 代码与文档约定

本文约定命名、C++ 规范边界、注释、文档与提交前检查。改动已有代码时保持与相邻模块一致，不为统一风格扩大范围。构建与 ABI 硬边界见 [构建与运行](build.md)。

## 命名与类型形态

- **类型按形态分大小写**：
    - `snake_case`：纯数据聚合（无用户声明构造函数、无成员函数、无虚函数，仅 public 数据成员）。
    - `PascalCase`：有封装、成员函数、构造/析构或虚函数的类；仿标准库协议的轻量辅助类型允许沿用小写。
- **函数、变量、参数、模板参数与 concept 均用 `snake_case`**：动作函数用动词短语，容器接口沿用标准库命名；布尔量优先用 `is_`/`has_` 前缀，计数/字节数/地址边界可用 `_count`/`_size`/`_base`/`_end` 后缀。
- **命名空间全小写**，保持简短。
- **成员变量**：封装类成员用 `m_` 前缀（不加 `this->`）；无 `m_` 前缀的公开数据成员在成员函数内必须通过 `this->` 访问。
- **文件级符号与常量**：内部可变状态用 `g_` 前缀；常量统一使用 `UPPER_SNAKE_CASE`。
- **修饰符顺序与精简**：按 `static` / `inline` / `constexpr` / `const` 惯用顺序书写（由 `.clang-format` 统一规范），避免语义冗余修饰符。常量默认用 `constexpr`，仅在跨翻译单元需要单一地址身份时使用 `inline constexpr`（例如 `device::interface_id`）。

## C++ 规范

默认遵循 [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)（RAII、值语义、`enum class`、显式初始化与转换、`constexpr`/`static_assert`、`[[nodiscard]]`/`noexcept`、头文件自包含等）。以下仅列出本内核在 freestanding 环境下的偏离与补充约束：

- **无异常、无 RTTI**：内核以 `-fno-exceptions -fno-rtti` 编译且无宿主运行时，禁用异常、`dynamic_cast` 与 `typeid`。可恢复错误通过返回值、`std::optional` 或 `std::expected` 显式表达，不依赖 `abort()` 或终止路径做错误处理。
- **错误处理分界**：内核不变量违反与调用方契约错误使用 `SEELE_ASSERT`/`panic`；可恢复的资源/分配失败返回失败值并明确是否留下部分修改，不静默修正非法输入。
- **静态存储优先与显式所有权**：内核生命周期对象优先使用静态存储或静态 arena（placement new），避免为永久对象分配堆页；裸指针不隐含所有权，新增动态资源必须明确释放者与生命周期。
- **锁与并发**：锁优先使用 RAII（`Spinlock` + `LockGuard`），不绕过锁自行改写 `sstatus.SIE`；**禁止持自旋锁调用 `sleep()`、`schedule()` 或 `yield()`**，详细契约见 [调度文档](scheduling.md)。`std::atomic` 显式指定内存序并说明同步意图。
- **强类型地址与段约束**：物理/虚拟地址统一使用 `Paddr`/`Vaddr`，经由 [addr.h](../src/kernel/mm/addr.h) 与 [vm.h](../src/kernel/mm/vm.h) 边界函数转换，不以裸整数替代。`constinit` 仅保证常量初始化，不代表只读，也不决定目标段位置。

## 注释

- 解释**意图、不变量与取舍**，不复述代码，不替代文档。
- **不得在注释中引用文档路径或章节号**；代码注释只描述当前文件与接口契约。
- 头文件写接口契约（参数范围、所有权、失败语义、调用时机与并发前提）；实现文件写局部机制与边界。
- 区间、方向与单位须明确（如半开区间 `[begin, end)`、字节/页），不留模糊表述；代码变更时同步更新注释。
- 不留无边界的 `TODO` 占位；未实现项统一记录在对应文档的限制/后续列表中。

## 文档规则

文档只回答代码局部回答不了的问题：架构方向、跨模块契约、设计取舍、操作流程与约定。

- 开篇说明文档定位；[README](../README.md) 只做入口，不重复子系统细节。
- **现状与计划分离**：正文只陈述当前已实现行为，未实现或后续规划单独列出。
- **只链接文件，不链接章节号**；不把头文件已有逐字段注释抄进文档。
- 合并即删除旧内容，同一事实只在一处维护。
- 中文行文，代码标识符、路径、代码块与单位保持原样；契约变更时同步更新文档与索引。

## 提交前

- **格式化**：统一运行 `pixi run format`（覆盖 C/C++、TS、Markdown、JSON、YAML 及基础文本卫生）；未跟踪文件用 `pixi run pre-commit run --files <files>`。
- **代码变更**：至少构建 Release 并在 QEMU 中验证受影响路径；涉及 ABI/libc/运行时或布局/并发不变量时，补跑 Debug 构建、核对 `nm -u` 输出及多 hart 启动（步骤见 [构建与运行](build.md)）。
- **纯文档变更**：核对引用的命令、默认值、相对链接及格式化结果，不必机械重编译内核。
- **说明变更与边界**：提交/交接时明确写出改动、已执行的验证及未覆盖路径，不把“编译通过”当作功能验证。
